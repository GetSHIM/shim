# shim v0.4.4

## Accounting

- **A started call without usage settles at its reservation (enterprise).** v0.4.3
  applied this rule to streams that end early. v0.4.4 applies it to every other way
  a call can end without usage after the provider was sent it: a timeout (the
  gateway's own read timeout, or a provider's 408 or 504), a provider 5xx, a client
  disconnect or cancel, and a 200 answer the gateway rejects afterwards, for
  example a Gemini answer with fewer candidates than were asked for. Until now these
  refunded the quota and the spend in full, so the provider's bill for them never
  reached `monthly_limit_usd` or the token quotas. They now settle at the reserved
  prompt and maximum output and the reserved cost, with `estimated` true, the rule
  a JSON answer without usage already followed. The request row still ends
  `failed` with `PROVIDER_USAGE_UNAVAILABLE`. Stale-reservation recovery does the
  same for a row whose provider call had started (`STALE_RESERVATION_RECOVERED`).
  A call that never reached the provider stage, or one the provider refused with a
  4xx, is still refunded.
- **A stream whose client reads slowly is no longer recovered as stale
  (enterprise).** The heartbeat that pushes a stream's reconciliation deadline
  forward ran only when the client read the next chunk, so a client that stopped
  reading past the deadline (about three minutes for Gemini) had its live stream
  ended by stale-reservation recovery, and the real settlement that followed was
  refused. The heartbeat now runs on a timer, every
  `GATEWAY_RECONCILIATION_INTERVAL_SECONDS`, from the first byte until the stream
  ends, whether or not the client reads; it renews the concurrency lease too. A
  failed heartbeat is logged by error type and retried on the next tick instead of
  ending the stream. A settlement refused with an accounting conflict (usually a
  terminal record stale recovery already wrote) now counts as
  `usage_settlement_total{status="conflict"}` with an error log naming the request
  id, instead of `status="failed"`. Known gap until the overall stream deadline
  lands: a client that never reads and never closes keeps its reservation renewed
  until the connection drops; the cost stays within the tenant's own budget.
- **A fallback attempt counts one request unit.** When a started attempt fails and a
  fallback rule sends the request on, the failed attempt keeps its request unit and
  the next attempt reserves none, so the whole request still counts one unit. An
  attempt the provider refused gives its unit back to the next attempt, as before.

## Privacy

- **Card and national ID numbers glued to a word are found.** A TCKN or card
  number joined to a word by `_` or a letter (`musteri_10000000146.pdf`,
  `card_4111-1111-1111-1111`, `TC10000000146`, an OpenAI message `name` such as
  `lookup_10000000146`) was not detected, so it reached the provider even with the
  type set to `block`. It is now masked, or refused under `block`; the Luhn and
  TCKN checksums still decide. Digit groups separated by any Unicode dash or a
  minus sign (non-breaking hyphen, en or em dash, wave dash, their small and
  fullwidth forms) read as hyphenated, and every Unicode format character (U+180E,
  tag characters) and every unassigned default-ignorable code point (U+2065) is
  dropped for detection like a zero-width space, so such a card, TCKN or IBAN is
  masked whole.
- **Rules read every dash as a hyphen too.** Term, template and regex rules match
  the same text as the detectors. A dash typed into a term, a template or a regex
  (`PRJ–\d{4}`) matches a hyphen and every other dash, so an existing rule keeps
  finding what it found. A regex that names a dash by escape (`\u2013`) no longer
  matches it: write `-`.
- **Restoring an answer no longer stalls the process.** For each placeholder-shaped
  token in an answer that no request masked (`<A_00000000>`), restoration searched
  every masked value, on the event loop. A request masking 10,000 values whose answer
  repeated 20,000 such tokens held every request on the process, `/health` among
  them, for seconds. Restoration now looks each token up once, so its time follows
  the answer's length whatever was masked, for JSON answers and streams alike.
- **A stream with a long run of spaces after `<` completes.** When the request had a
  masked value, a stream answer holding `<` and more than 256 spaces or line breaks
  ended in `PROVIDER_UNAVAILABLE`. That text is now sent as written once it passes
  256 characters, and the stream goes on.

Upgrading: nothing to configure, and no API, error code or setting changes; a
pattern rule regex that names a dash by escape should name `-` instead. A key
that hits timeouts or provider errors reaches its `monthly_limit_usd` or token quota
sooner and is then refused with the same codes as any key over its limit. The figure
is the most the call could have cost, so it is never under-charged. A connection
the provider never accepted (connection refused) also settles at the reservation,
because the gateway does not yet tell it apart from a connection lost mid-call.
`gateway.repeat_spend` now counts a client retry after such a call as a billed
repeat, since the earlier call carries a spend settlement. Such a call writes no
answer snapshot (`provider_latency_ms`, `answer_characters`, `tool_call_names`,
`reasoning_seen`).
