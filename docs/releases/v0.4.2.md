# shim v0.4.2

A patch release on v0.4.1, with one behaviour change. No migrations and no new
settings; community and enterprise upgrade by image alone.

## Behaviour change

- **Turkish person names are masked by default.** `PERSON_NAME_TR` was `off` until
  an action turned it on; its default is now `mask`. "Sayın Ahmet Yılmaz'ın
  başvurusu" reaches the provider as "Sayın <PERSON_NAME_TR_…>'ın başvurusu", and
  the name is restored in the answer. This applies to every community install that
  does not set `PERSON_NAME_TR` in `PII_ENTITY_ACTIONS`, and to every enterprise
  tenant whose `entity_actions` does not set it. A setting stored before the upgrade
  is kept, `mask`, `monitor`, `block` or `off`. No group switch covers names: turning
  every `block_*` switch off still masks them. `/v1/scan`, the enterprise compliance
  scan and the tenant's effective actions in `GET /api/v1/management/settings/pii`
  report the new default too. Detection is the same list-based recognizer as
  v0.4.0 (held-out precision 0.992, recall 0.952); what it misses is in the
  [cookbook](../COOKBOOK.md#choose-what-happens-to-each-data-type).

  The detector costs a little more per request with names on: on the
  `scripts/bench_middleware.py` prompt, about 0.4 ms at 1 KB and 10 ms at 32 KB.

## Upgrading

To keep the v0.4.1 behaviour, set the type to `off` before upgrading: in community,
add `"PERSON_NAME_TR":"off"` to `PII_ENTITY_ACTIONS`; in enterprise, add it to the
tenant's `entity_actions` with `PUT /api/v1/management/settings/pii`, which replaces
the stored overrides whole, so send the ones you already have with it. `monitor`
sends names unchanged and counts them.

A gateway or tenant that turned every other type off now still masks names, so it
is no longer one that "masks nothing". With `SHIM_MEDIA_INPUTS=block` (enterprise:
`media_inputs: block`), the default, its requests carrying images or files are now
refused with 400 `PRIVACY_POLICY_BLOCKED`, as the
[cookbook](../COOKBOOK.md#choose-what-happens-to-each-data-type) describes for any
gateway that masks, until `PERSON_NAME_TR` is `off` or media inputs are allowed.

Rolling back is the previous image (v0.4.1); nothing is stored differently.
