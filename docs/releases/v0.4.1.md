# shim v0.4.1

A patch release on v0.4.0. No migrations, no new settings and no breaking changes;
community and enterprise upgrade by image alone.

## Fixes

- **Embeddings no longer answer 500 with a transform on.** In v0.4.0,
  `POST /v1/embeddings` and the Gemini `:embedContent` and `:batchEmbedContents`
  routes failed with 500 whenever JSON compaction or image downscaling was on:
  `SHIM_JSON_COMPACTION=on` or `SHIM_IMAGE_DOWNSCALE=on` in community, and
  `transforms.json_compaction` or `transforms.image_downscale` set to `on` through
  `PATCH /gateway-settings` in enterprise. The transform band measured tool results
  for every protocol before checking whether its steps apply, and embeddings carry
  none. They now pass through the band untouched, with `transforms_applied: []`.
  Chat, Responses, Anthropic messages, Gemini `generateContent` and token counting
  were never affected.
- **`image_downscale` records images it left alone.** A request whose every inline
  image was skipped (for example `too_large`, `below_threshold` or
  `client_opt_out`) had no `image_downscale` entry in `transforms_applied`, though
  the [cookbook](../COOKBOOK.md#shrink-oversized-images) says the entry lists
  skipped images by reason. It now gets the entry with `items` 0 and the reasons
  under `skipped`. Such a request counts as `unchanged` in
  `shim_transforms_total` and adds nothing to the savings record.

## Upgrading

Nothing to do. If you turned JSON compaction or image downscaling off to work
around the embeddings error, you can turn it back on.

## Rolling back

To v0.4.0 by image alone: no schema changed. On Cloud Run,
`gcloud run services update-traffic <service> --to-revisions=<revision>=100`.
Going further back follows the [v0.4.0 notes](v0.4.0.md#rolling-back).
