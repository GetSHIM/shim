# shim v0.4.1

A patch release on v0.4.0. No migrations, no new settings and no breaking changes;
community and enterprise upgrade by image alone. Detection masks more disguised
identifiers and fewer invoice numbers; see [benchmark findings](#benchmark-findings).

## Fixes

- **Embeddings no longer answer 500 with a transform on.** In v0.4.0,
  `POST /v1/embeddings` and the Gemini `:embedContent` and `:batchEmbedContents`
  routes failed with 500 whenever JSON compaction or image downscaling was on:
  `SHIM_JSON_COMPACTION=on` or `SHIM_IMAGE_DOWNSCALE=on` in community, and
  `transforms.json_compaction` or `transforms.image_downscale` set to `on` through
  `PATCH /gateway-settings` in enterprise. The transform band measured tool results
  for every protocol before checking whether its steps apply, and embeddings carry
  none. They now pass through the band untouched, with `transforms_applied: []`.
  Chat, Responses, Anthropic messages, Gemini `generateContent` and token counting
  were never affected.
- **`image_downscale` records images it left alone.** A request whose every inline
  image was skipped (for example `too_large`, `below_threshold` or
  `client_opt_out`) had no `image_downscale` entry in `transforms_applied`, though
  the [cookbook](../COOKBOOK.md#shrink-oversized-images) says the entry lists
  skipped images by reason. It now gets the entry with `items` 0 and the reasons
  under `skipped`. Such a request counts as `unchanged` in
  `shim_transforms_total` and adds nothing to the savings record.
- **Email detection no longer downloads the Public Suffix List.** In v0.4.0 the
  first email address a process checked made an HTTPS request to `publicsuffix.org`
  (and its GitHub mirror) with no timeout, once per container start, and cached it
  on disk; with a firewall that drops packets, that first request could stall.
  Email domains are now checked against the list bundled with `tldextract` (snapshot
  of 2025-04-07), with no network call and no disk cache. The request carried nothing
  from the prompt. Installs that already ran with egress closed were using this
  bundled list and see no change. Against the live list, 12 of 6,949 suffixes decide
  differently: an address at `.hotel` or `.web` (added since), or directly under
  `.bd` or `.kh` (`x@example.bd`), is not taken for an email; one at eight retired
  brand TLDs, such as `.goo`, still is.

## Benchmark findings

The PII benchmark of 15 October 2026 (1,040 disguised identifiers, 480 labelled
documents) found five disguises that got an identifier past detection, a phone rule
that took invoice numbers for phones, and a cache setting that cost more than it
saved. All three are fixed; no identifier type lost recall.

- **Disguised identifiers are masked.** Detection now reads a TCKN, card, IBAN or
  phone number with a space between every character (`1 0 0 0 0 0 0 0 1 4 6`) or in
  hyphenated groups of one size (`TR3-300-061-005-...`, `411-111-111-...`) without
  the separators; an email broken over a line after its `@`; marks on the letters of
  an email or IBAN; and a value stored reversed after a right-to-left override
  (U+202E), which is read in both the stored and the shown order. The mask covers
  the separators, marks and reversed text, and the answer restores the original.
  Benchmark leak rates, before and after: spaces 70% to 0%, reversed override 86%
  to 0%, line break 100% to 0%, marks 40% to 0%, hyphen groups 49% to 0%.
- **Fewer invoice, order, tracking numbers and dates masked as phones.** `no` and
  `numaranız` after `fatura`, `sipariş`, `order`, `invoice` or `takip` no longer make
  a number a phone; `tel no`, `telefon no` and `cep no` still do, and a number shaped
  like a Turkish mobile (`5xx xxx xx xx`) is still masked. A date such as
  `05.03.2026` is not a phone. Benchmark: invoice numbers masked 86.7% to 7.8%,
  dates 10% to 0%, tracking numbers 3.3% to 0%, order numbers 8.3% to 5.4%;
  precision 89.1% to 96.8% at unchanged recall.
- **`SHIM_ANTHROPIC_AUTO_CACHE` reads a shared system prompt back.** Its only
  breakpoint was the top-level one, after the last message, so independent requests
  that share a system prompt each wrote a cache entry and none was read: 25% more
  input cost. The same marker now also goes on the last `system` block (a string
  `system` is sent as one text block), two of Anthropic's four breakpoints; a
  request with its own breakpoints is still sent as it is. Two live
  `claude-sonnet-4-6` requests with a 2,330-token system prompt: before, both wrote
  2,337 tokens; after, the second read 2,329 and wrote 9. In enterprise the same
  applies to `provider_cache.anthropic_auto_cache`.

## Upgrading

Nothing to do. If you turned JSON compaction or image downscaling off to work
around the embeddings error, you can turn it back on.

## Rolling back

To v0.4.0 by image alone: no schema changed. On Cloud Run,
`gcloud run services update-traffic <service> --to-revisions=<revision>=100`.
Going further back follows the [v0.4.0 notes](v0.4.0.md#rolling-back).
