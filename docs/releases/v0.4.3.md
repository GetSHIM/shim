# shim v0.4.3

A patch release on v0.4.2, with one accounting fix. No migrations and no new
settings; community and enterprise upgrade by image alone.

## Fix

- **A stream cut before its final usage settles at the reservation.** When a
  stream ended before the provider sent its final usage, most often because the
  client hung up after the first token, the gateway settled the output at one token
  per four characters the client had received. Hidden reasoning, and output the
  provider produced after the hang-up, were never counted, so a key could cut every
  stream early and keep its spend and token counters near zero: enterprise
  `monthly_limit_usd` never refused and token quotas never filled. Such a stream now
  settles its output at the reserved maximum (the request's `max_tokens`, or the
  model's output limit, times the candidates asked for) with `estimated` true, as
  a JSON answer without usage already did. A provider-reported prompt count is
  kept. The rule covers chat
  completions, Responses, Messages and Gemini streams, and also streams that end
  in a provider error or timeout. Only a completed stream's output count is taken
  as the bill: running counts sent before that (Gemini repeats them on every
  chunk, Anthropic sends one before `message_stop`) are not.

## Upgrading

Nothing to configure. Usage records and the community usage log show larger,
estimated `completion_tokens` and cost for streams that ended early; completed
streams with provider usage are unchanged. In enterprise, a key that cut streams
early reaches its `monthly_limit_usd` or token quota sooner than before and is then
refused with the same codes as any key over its limit. An early-ended
stream is counted at what was reserved for it, the most it could have cost, so it is
never under-charged. Nothing lowers that count afterwards: the gateway stops reading
a stream when it ends, so it never sees the provider's own usage for it.

## Not in this release

v0.4.3 carries this one fix so it can ship on its own. The same rule for the other
ways a started call can end without usage, a non-streaming call that times out or is
cancelled after the provider started and a reservation recovered as stale, comes in
v0.4.4, with the privacy scan limits and their new refusal codes, strict model ids in
the price book, `.docx` sent as extracted text and the patched base image. This
release changes no API, error code or setting.

## Rolling back

To v0.4.2 by image alone: no schema changed and nothing is stored differently. On
Cloud Run, `gcloud run services update-traffic <service> --to-revisions=<revision>=100`.
Going further back follows the [v0.4.1 notes](v0.4.1.md#rolling-back).
