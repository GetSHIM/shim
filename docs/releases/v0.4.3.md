# shim v0.4.3

A patch release on v0.4.2, with one accounting fix. No migrations and no new
settings; community and enterprise upgrade by image alone.

## Fix

- **A stream cut before its final usage settles at the reservation.** When a
  stream ended before the provider sent its final usage, most often because the
  client hung up after the first token, the gateway settled the output at one token
  per four characters the client had received. Hidden reasoning, and output the
  provider produced after the hang-up, were never counted, so a key could cut every
  stream early and keep its spend and token counters near zero: enterprise
  `monthly_limit_usd` never refused and token quotas never filled. Such a stream now
  settles its output at the reserved maximum (the request's `max_tokens`, or the
  model's output limit, times the candidates asked for) with `estimated` true, as
  a JSON answer without usage already did. A provider-reported prompt count is
  kept. The rule covers chat
  completions, Responses, Messages and Gemini streams, and also streams that end
  in a provider error or timeout. Only a completed stream's output count is taken
  as the bill: running counts sent before that (Gemini repeats them on every
  chunk, Anthropic sends one before `message_stop`) are not.

## Upgrading

Usage records and the community usage log show larger, estimated
`completion_tokens` and cost for streams that ended early; completed streams with
provider usage are unchanged. Rolling back is the previous image (v0.4.2); nothing
is stored differently.
