# shim v0.4.5

A patch release on v0.4.4. `shim serve` gets two process guards, a startup-hook
guard and an egress guard, both reporting by default, and the release and CI image
smoke steps run them in `enforce`. The documentation installs the image by digest
and shows how to verify it. Pillow, pypdf and four other shipped packages get
security updates, in both images. No migrations; the community gateway gains three
settings, and the enterprise gateway's code does not change.

Background: on 21 October 2026 LiteLLM 1.107.0 shipped a credential stealer as a
`.pth` startup hook. How shim's release is built, what its attestation proves, and
what these guards do not cover are in [supply chain](../SUPPLY_CHAIN.md).

## Process guards

- **Startup-hook guard** (`SHIM_STARTUP_GUARD`: `off`, `report`, `enforce`; default
  `report`). At start, `shim serve` looks for `.pth` files with import lines, the
  modules they import, and `sitecustomize` or `usercustomize`, and compares them by
  path and sha256 with the hooks the published image ships (uv's `_virtualenv` and
  setuptools' `distutils-precedence`). Each other one is logged as
  `startup_hook_unexpected` with its path, kind and sha256, and counted in
  `shim_startup_hooks_unexpected`. `enforce` exits with code 78 before serving.
- **Egress guard** (`SHIM_EGRESS_GUARD`: `off`, `report`, `enforce`; default
  `report`; extra hosts in `SHIM_EGRESS_ALLOW_HOSTS`). A Python audit hook installed
  before the server starts checks name lookups and connections. Names other than the
  configured provider, Azure, OTLP and Sentry hosts, `localhost` and the listed
  hosts, and connections to cloud instance metadata or other link-local addresses,
  are logged once per destination as `egress_denied` and counted in
  `shim_egress_denied_total{kind,mode}`. `enforce` makes the call fail with
  `PermissionError` before any DNS query. Under `enforce` the PDF and image worker
  processes refuse all network access.
- Both guards are installed by `shim serve` only. An application that calls
  `create_community_app` itself gets neither.
- Cost: about 90 ns per audited Python event, about 0.1 ms on a 32 KB request,
  below what [the benchmark](../BENCHMARKS.md) can measure.

## Dependencies

Security updates for packages the image ships, from advisories published on
24 October 2026:

- **Pillow 12.3.0 → 13.0.0** (`images` extra). Fixes four critical and many high
  advisories in its decoders, including a JPEG decoder buffer overflow. shim decodes
  untrusted images with it, in the isolation workers, when `SHIM_IMAGE_DOWNSCALE` is
  on. None of the 13.0.0 removals touch shim's use (open, EXIF, mode conversion,
  `draft`, LANCZOS resize, save).
- **pypdf 6.20.1 → 6.21.2** (`documents` extra). Fixes three high and several medium
  advisories (unbounded parsing work, the size of the cross-reference table). shim
  reads untrusted PDFs with it when `SHIM_DOCUMENTS` is on.
- **filelock 3.32.0 → 4.2.4**, **setuptools 83.0.0 → 84.2.1** and the
  **OpenTelemetry** packages **1.45.0 → 1.45.1** (exporters with them).

setuptools 84.2.1 changes `_distutils_hack/__init__.py`, one of the startup files the
image ships, so its hash in the startup-hook allowlist changes in the same release.
Built with the old hash, the image exits with 78 and names that file, which is what
the guard is for.

## Release

- The CI and release image smoke steps run with `SHIM_STARTUP_GUARD=enforce` and
  `SHIM_EGRESS_GUARD=enforce`. A dependency update that brings a new startup hook
  fails the pull request. In a release, `latest` and the version tag are pushed
  before the smoke step runs, so a failure there stops the GitHub release but not
  the tags.
- The README, the cookbook and `SECURITY.md` install and verify the image by digest.

## Upgrading

- **Logs.** A gateway that works today keeps working. It can gain WARNING lines:
  `startup_hook_unexpected` when its Python carries hooks the image does not ship
  (conda's Python ships a `sitecustomize`), and `egress_denied` for a host the
  gateway resolves that is not configured, such as a proxy.
- **Before `enforce`.** List every proxy or extra upstream host in
  `SHIM_EGRESS_ALLOW_HOSTS` (comma-separated; an exact host or `*.` and a suffix;
  no scheme, path or port). Run in `report` first and read the `egress_denied` lines.
- **Local development.** Set `SHIM_STARTUP_GUARD=off` when your Python carries its
  own `sitecustomize`.
- **Your own image.** An image built on the published one that adds a package with
  a startup hook is reported, and refused under `enforce`.

## Not in this release

- A guard for processes started with `subprocess` or `os.exec*`.
- Checking a connection to a literal public IP against the names resolved before it.
- The guards in the enterprise gateway and its workers.

## Rolling back

No migrations. Roll back by moving traffic to the v0.4.4 revision, or set both
guards to `off`.
