# shim v0.4.8

A patch release on v0.4.7. No migrations and no new settings; community and
enterprise upgrade by image alone.

## Compatibility

- **Responses timestamps are integers again.** `created_at` and `completed_at` on a
  Responses answer, and on the response inside every Responses stream event, left
  shim as floats (`1794071243.0`) where OpenAI sends integers (`1794071243`). The
  OpenAI SDK, which shim reads each answer through, types both fields as floats.
  Lenient clients, Codex CLI among them, read either. Strictly typed clients refused
  the answer: goose 1.57, which sends every `gpt-5.x` and `gpt-6.x` model through
  the Responses API, failed each request with `invalid type: floating point …,
  expected i64`. shim now forwards the integer OpenAI sent; a fractional value passes
  through unchanged. A failed response with no usable `created_at` gets `0`, not
  `0.0`.

## Upgrading

Nothing to change.

## Rolling back

To v0.4.7 by image alone: no schema changed and nothing is stored differently.
