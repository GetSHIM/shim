# shim v0.4.7

A patch release on v0.4.6. No migrations and no new settings; community and
enterprise upgrade by image alone.

## Privacy

- **Wider secret detection.** Each of these reached the provider unmasked, and
  `/v1/scan` called it `clean`:
  - AWS: temporary key ids (`ASIA…`, as `AKIA…` already was) and the 40-character
    secret access key after its name in any spelling (`aws_secret_access_key =`,
    `AWS_SECRET_ACCESS_KEY=`, `"SecretAccessKey":`, `secretAccessKey:`,
    `AWS Secret Key:`, `--aws-secret-access-key`, `… secret access key is …`) or
    right after the key id it belongs to (`AKIA…,…` in the console's CSV).
  - Provider tokens in any context, not only after a key name: GitHub fine-grained
    tokens (`github_pat_`), Google OAuth access tokens (`ya29.`), Slack app tokens
    (`xapp-`) and rotated Slack tokens (`xoxe-`, `xoxe.xoxp-`). Before, a token in a
    `Bearer` header or in prose was visible apart from a tax-number placeholder on
    a ten-digit run inside it.
  - Key names built on a secret word: `password_confirmation`, `password1`,
    `DB_PASSWORD_PROD`, `SECRET_KEY`, `secretKey`, after `=` or `:` and, as before
    for the bare word, after a space when the value carries a digit or a symbol
    (`setenv DB_PASSWORD_PROD hunter2!`). A lower-case letter glued to the word
    makes another word (`tokens`, `passwordless`, `MAX_TOKENS`), which is not a key.
  - Turkish keys take any Turkish ending (`şifremiz:`, `parolamız:`), checked with
    the grammar tenant terms already use; `şifreleme:` is not a key.
  - Short values. After `=` or `:` a value of any length on the key's line is
    masked (`password: x`, `şifre: 1234`, `DB_PASSWORD=r00t!`, quoted
    `password: "Ab1!x"`); the six-character minimum stays for the spaced form and
    for a value on the next line. A PIN of four to six digits is masked after
    `şifre`, `parola` or `PIN` with a space alone too (`kart şifrem 4821`).
  - Markdown labels: `**Password:** hunter2` and `**Password**: hunter2`.
  - A quoted value runs to a quote that ends it, so `password='it's'` and an
    escaped quote inside a value are masked whole.
- **Database URLs with a driver or TLS.** `postgresql+asyncpg://`,
  `postgresql+psycopg2://`, `mysql+pymysql://`, `mssql+pyodbc://`, `mariadb://`
  and `rediss://` are `DB_URI`, as `postgres://` and `redis://` were; a password
  holding an unencoded `/` stays inside the match. Before, the password reached
  the provider unless the host happened to be a dotted domain.

### Changes you may notice

Detection is wider, so more is masked, and a tenant that set `SECRET` or `DB_URI`
to `block` sees more `SECRET_BLOCKED` refusals.

- **A database URL without credentials is no longer `DB_URI`.**
  `redis://localhost:6379/0` holds nothing secret and is left alone; any URL with
  a user part (`user@`, `user:pass@`, `:pass@`) is masked whole. An `@` later in
  the same URL counts too (`redis://host/0?x=a@b` is masked).
- **Over-masking after an explicit separator.** A short value after a key name is
  masked even when it is not a secret: prose after a label
  (`Password: Use at least 8 characters` masks `Use`), a count under a camel-case
  key (`promptTokenCount: 12`, `token_count: 5`), a config value under a key that
  names a secret (`SECRET_BACKEND=gcp_secret_manager`). JSON literals
  (`"password": null`, `"token": true`), an object or array opened after the key
  (a schema), and an empty quoted value are left alone.
- **A four-to-six-digit number after `şifre`, `parola` or `PIN`** is masked as a
  PIN, a year included (`Parola 2026 politikası`); a date (`PIN 2026-10-21`) or a
  decimal is not.

### Known limits

- A suffixed key with a value on the next line still needs six characters, as the
  bare key did.
- spaCy's tokenizer is slower than linear on one very long token with no
  whitespace (a full scan of `redis://` repeated 8,192 times takes seconds, as in
  v0.4.4); the per-request scan deadline and text cap from v0.4.4 bound it.

## Upgrading

Nothing to change. Prompts that carried the secrets above now reach the provider
with placeholders, which the answer restores as before.

## Rolling back

To v0.4.6 by image alone: no schema changed and nothing is stored differently.
