# shim v0.4.0

Upgrade notes for operators coming from v0.3.0 or v0.3.1. Community needs no data
step; enterprise runs 24 migrations. Every new feature is off until you turn it on,
except the few listed under [what changes with default settings](#what-changes-with-default-settings).

## Breaking changes

- **Findings API (enterprise).** `GET /findings`, `GET` and `PATCH /findings/{id}`
  answer in the published [Finding v1](../FINDINGS_SCHEMA.md) shape. The v0.3.0
  shape is gone: `summary` is `{en, tr}`, `severity_id` is `severity`, `subject` is
  `{kind, id}`, `first_seen_at`/`last_seen_at` are `window`, `impact.cost_usd` is
  `impact.usd`, `remediation.doc` is `playbook`. The `?status=` filter and the
  `PATCH` body still accept the v0.3.0 values. Field-by-field map:
  [what changes for existing apps](../FINDINGS_SCHEMA.md#what-changes-for-existing-apps).
- **Only a key's owner can rotate it (enterprise).** `POST /api-keys/{id}/rotate`
  answers 403 to an organization admin or a team admin rotating someone else's key.
  They can still revoke it. The console should hide **Rotate** on keys the viewer
  does not own.
- **Management routes ask for named permissions (enterprise).** Every management
  route checks one named permission; a role without it is refused. `keys.manage` is
  owner and admin only, and members can read gateway settings.
  [Permissions](../../ee/docs/team-access.md#permissions).
- **422 bodies never echo the input.** A request refused by validation lists its
  errors without their `input` field, so a key or secret in a refused body is not
  sent back. v0.3.1 already does this.
- **Model ids are checked.** An id longer than 200 characters, or with a character
  other than letters, digits, `.`, `_`, `:` and `-`, is refused: 400
  `MODEL_NOT_PRICED` in community, 403 `MODEL_NOT_REGISTERED` in enterprise.
- **Usage CSV (enterprise)** gains a `provider_latency_ms` column. Read columns by
  header, not by position.

## What changes with default settings

- **New routes:** `POST /v1/embeddings`, and Gemini `:embedContent` and
  `:batchEmbedContents`, with the same privacy rules as chat. Errors on
  `/v1/embeddings` use OpenAI's error shape. Embedding models answer only these
  routes and are not listed in `/v1/models`.
  [Send embeddings through shim](../COOKBOOK.md#send-embeddings-through-shim).
- **Agent-loop signal is on as a count.** `SHIM_AGENT_LOOP=count` (enterprise:
  `agent_loop`) records `tool_call_repeats` and `task_calls` on the usage event and an
  `AGENT_LOOP_SUSPECTED` verdict at 5 repeats. It refuses nothing unless set to `block`.
- **Identical in-flight requests are counted:** `inflight_duplicate_of` on the
  usage event and `shim_inflight_duplicates_total`. Nothing is shared unless
  sharing is turned on.
- **Retirement dates are recorded:** `MODEL_RETIRING` and `MODEL_RETIRED` appear
  in the usage event's `warnings`; response headers change only with
  `SHIM_MODEL_RETIRING_WARNING=header`. shim never refuses or reroutes a model for
  its date.
- **Request records carry more facts:** provider latency, answer size, tool names,
  protocol, and the task id from `X-Shim-Task-Id`. A task id made only of 10 or
  more digits is ignored.
- **Forwarded media is sized by its parts.** Where images and files already pass
  (`SHIM_MEDIA_INPUTS=allow`, or no type masks or blocks), rate limits and the
  spend reservation count an image at what its provider bills, not at its base64
  size. [Choose what happens to each data type](../COOKBOOK.md#choose-what-happens-to-each-data-type).
- **OpenAI answers carry only the fields the provider sent.** v0.3.x added unset
  SDK fields such as `status: null` to a reasoning item, which made a replayed
  Responses `input` fail with 400.
- **Detection fixes**, also in v0.3.1: identifiers written in any script's digits
  (Arabic-Indic, Devanagari, Bengali and others) and digits followed by combining
  marks or invisible characters are masked; a lone surrogate in a request is a
  400 `INVALID_REQUEST` before privacy, not a 5xx.
- **Turkish tax numbers use the official VKN checksum.** v0.3.x rejected about 61%
  of valid VKNs, and those reached the provider unmasked. A ten-digit number that
  is both a valid VKN and a valid phone number is masked as `PHONE_NUMBER` unless
  `vergi`, `VKN` or `tax` is in front of it, so per-type counts and actions can
  move between the two.
- **Enterprise reads and findings that need no switch:** policy versions for
  every change, the deployment that served each request, the model inventory from
  traffic, outcome filters and rates, latency per team and app, cost per agent task,
  the Turkish KVKK report with the organization name, the access section in the
  monthly evidence file, readiness next steps, incident records, rule previews, the
  savings read and the model evidence document. New finding rules that read only
  stored records run on their own; the ones that need an analyzer stay quiet until
  it is on.

## Before you upgrade (enterprise)

1. `alembic -c ee/alembic.ini current` should print `7e3fb2338f03`, the head of
   v0.3.0 and v0.3.1. The first new revision, `24b8466be324`, follows it; the chain
   is linear with one head, `e8cb8fb75cb0`.
2. Rows written by v0.3.x pass the new check constraints: `ck_users_role` and
   `ck_users_service_role` only widen, `ck_users_custom_role_member` and
   `ck_teams_aws_cost_tag` read new columns that start `NULL`, and
   `ck_provider_secrets_role_shape` holds for every secret that has its
   `secret_ref`, `secret_backend` and `secret_version`, as v0.3.x required. New
   columns on existing tables are nullable or carry a server default.
3. `e8cb8fb75cb0` drops `request_logs.cost_saved` and `request_logs.tokens_saved`.
   Nothing has written them since the semantic cache was removed. Check before
   upgrading that no value would be lost:

   ```sql
   SELECT count(*) FROM request_logs WHERE cost_saved <> 0 OR tokens_saved <> 0;
   ```

   A non-zero count is data from an older build; export it first if you need it.
   Savings now live per request in the request record (`savings`).
4. Run `alembic -c ee/alembic.ini upgrade head` before the new image takes traffic,
   as for every release.

## Rolling back

A traffic rollback below v0.4.0 needs one schema step first. An image older than
`e8cb8fb75cb0` writes `request_logs.cost_saved` and `tokens_saved`; against the
v0.4.0 schema those writes fail and the outbox retries them until they dead-letter.
So, before moving traffic to a v0.3.x revision:

```console
alembic -c ee/alembic.ini downgrade c6bf1ec40802
```

Then move traffic to the older image (on Cloud Run,
`gcloud run services update-traffic <service> --to-revisions=<revision>=100`).

The downgrade adds both columns back with a default of 0, so v0.4.0 workers still draining during the switch keep writing. The other 23 revisions are additive and
an older image ignores them, so stop there. A full downgrade to `7e3fb2338f03`
drops every new table and its data (policy versions, incidents, record sets,
approvals, archives, credentials), and is for disposable databases only. Community
has no schema and rolls back by image alone.

The published image `ghcr.io/getshim/shim` is built with both extras; the
settings that use them stay off. `shim-enterprise` depends on pypdf and Pillow
directly, so the image from `ee/Dockerfile` has them too, but not `archive-s3`
unless built with `--build-arg ENTERPRISE_EXTRAS=archive-s3`. A source install
without an extra logs a warning at start when its setting is on: without pypdf a
PDF is unscannable, without Pillow downscaling stays off.

## Features

Marked **default** (works without a switch, usually a record or a read) or
**opt-in**. EE is enterprise only.

### Privacy

- Turkish person names (`PERSON_NAME_TR`), list based, never a model. **Opt-in**
  (action `off` by default). [Data types](../COOKBOOK.md#choose-what-happens-to-each-data-type)
- Images and files: one classifier, a switch to let them through unscanned.
  **Opt-in** (`block` by default). [Data types](../COOKBOOK.md#choose-what-happens-to-each-data-type)
- PDF, Word and text files read and checked like message text, or sent as their
  masked text. **Opt-in**. [Data types](../COOKBOOK.md#choose-what-happens-to-each-data-type)
- Instructions hidden in tool results and documents counted or warned about, never
  blocked. **Opt-in**. [Hidden instructions](../COOKBOOK.md#count-instructions-hidden-in-tool-results)
- EE: the tenant's own words and codes found in every Turkish suffix form.
  **Opt-in**. [Privacy settings](../../ee/docs/COOKBOOK.md#change-the-privacy-settings)
- EE: destination rules, "this type never goes outside". **Opt-in**.
  [Keep a data type inside](../../ee/docs/COOKBOOK.md#keep-a-data-type-inside)
- EE: requests matched against keyed hashes of a customer list or confidential
  documents; the plain values never leave your machine. **Opt-in**.
  [Catch your customer list](../../ee/docs/COOKBOOK.md#catch-your-customer-list)
- EE: restore permission per team and key, so other callers keep the placeholder.
  **Opt-in**. [Masked values for some teams](../../ee/docs/COOKBOOK.md#show-masked-values-only-to-some-teams)

### Evidence and compliance (EE)

- KVKK report in Turkish with the organization name; "who accessed what" in the
  monthly evidence file. **Default**.

  (entitled tier). [Readiness](../../ee/docs/COOKBOOK.md#prepare-for-isoiec-42001)

  until an admin marks a breach. [Incidents](../../ee/docs/INCIDENTS.md)
- Request archive: rule-matched requests kept 90 days, opened only by an admin,
  every opening visible. **Opt-in**, self-hosted only.
  [Archive](../../ee/docs/COOKBOOK.md#keep-matched-requests-and-open-one)

  self-hosted only. [Ask the archive](../../ee/docs/COOKBOOK.md#ask-the-archive-your-own-questions)
- Live semantic check on one marked endpoint; it can only warn. **Opt-in**.
  [Marked endpoint](../../ee/docs/COOKBOOK.md#mark-an-endpoint-for-a-live-semantic-check)

## Known limits

- Image metadata (EXIF, XMP) on a forwarded image is neither scanned nor removed;
  only a downscaled image loses it. Scanned PDFs without a text layer are not read.
- `mailto:` targets inside a Word file are not scanned.
- Change-test copies can exceed `max_requests` by a few per process.
- Real-credential checks were not run for Azure OpenAI and for a Bedrock AWS role.
